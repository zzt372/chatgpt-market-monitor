# chatgpt-market-monitor

ChatGPTの「マーケット指標監視」タスクで使用する、市場データ取得用リポジトリです。

各指標はディレクトリとGitHub Actions workflowを分離しています。1つの取得処理が失敗しても、他の指標の更新・通知判定を止めません。NASDAQ100 Forward P/E監視は2026-10-18に廃止しました。

## 監視対象

| 指標 | 出力JSON | 主な取得元 |
|---|---|---|
| CNN Fear & Greed | `monitors/cnn-fear-greed/latest.json` | CNN公式JSON |
| NASDAQ100の直近3年の最高終値からの下落率 | `monitors/nasdaq-drawdown/drawdown.json` | Nasdaq公式ヒストリカルAPI |
| SOXの直近3年の最高終値からの下落率 | `monitors/sox-drawdown/drawdown.json` | Nasdaq公式ヒストリカルAPI |
| S&P500の直近3年の最高終値からの下落率 | `monitors/sp500-drawdown/drawdown.json` | Cboeの公開データ（遅延配信の履歴・現在値） |
| 日経平均の直近3年の最高終値からの下落率 | `monitors/nikkei-drawdown/drawdown.json` | FRED（米セントルイス連銀）経由の日本経済新聞社の公式終値 |

## 指数の通知条件

ポリシーv3（2026-11-10〜）です。NASDAQ100・S&P500・SOX・日経平均は独立して判定し、通知済みの段階・再通知を開始できる状態も指数ごとに保存します。大暴落でのスポット購入を検討するための通知なので、段階は大きな下落に絞っています。

| 段階 | NASDAQ100 | S&P500 | SOX | 日経平均 | 過去の頻度の目安（米国の3指数） |
|---|---:|---:|---:|---:|---|
| 1 | −20% | −15% | −30% | −20% | 約4年に1回 |
| 2 | −30% | −20% | −40% | −30% | 約8年に1回 |
| 3 | −40% | −30% | −50% | −40% | 約10〜13年に1回 |
| 4 | −50% | −40% | −60% | −50% | 2000年・2008年級 |

段階は、3年高値比の過去の到達回数から、米国の3つの指数で同じくらい珍しい水準にそろえています（S&P500は値動きが小さく、SOXは大きいため）。日経平均（2026-11-10に追加）はNASDAQ100と同じ段階です。日経平均は米国と別に暴落することがあり、1980年以降、米国の2指数（S&P500・NASDAQ100）に通知が出ない年に日経平均だけが通知に届いたことが7回あります（1992年、1997年に2回、2013年、2016年、2024年8月、2026年11月）。

通知を判定する下落率は次の式です。現在日を含む直近3年（756取引日）の終値を使用します。全履歴最高終値（ATH）からの下落率と、同じ指数の過去の主な暴落の底（`policy.json` の `reference_bottoms_pct`）も通知本文に参考情報として添えますが、通知判定・再通知の条件には使用しません。

```text
drawdown_3y_pct = (current_close / high_3y_close - 1) * 100
```

現在値には取引時間中の価格ではなく、確定した終値を使います。年初来騰落率や前日比とも異なります。閾値の判定には丸め前の `drawdown_3y_pct` を使用し、表示時だけ丸めます。

### 基準を「直近3年の最高値」にした理由

2026-11-10に、`alerts.py` の状態遷移をそのまま過去のデータに当てはめて比べました。対象はNASDAQ100、S&P500、SOX（1994年5月以降）、ナスダック総合指数（1971年〜、FRED）、日経平均（1949年〜、FRED）、米国株（1871年〜、Shiller教授の月次データ）です。

| 基準の高値 | 結果 |
|---|---|
| 全履歴最高値 | 昔の高値を取り戻す前に来た暴落を丸ごと見逃した（NASDAQ100・SOXの2008年、日経平均の1992〜2024年の32年間、米国株の1937〜38年など） |
| 直近252取引日（v2） | 長く続く下落を浅く測った（NASDAQ100の2000〜02年は−67.4%。実際は−82.9%） |
| 直近4年・5年 | 3年なら捉えた暴落の一部を逃した（S&P500の2011年、SOXの2006年・2011年、5年では日経平均の1997〜2001年など） |
| **直近3年** | 上の暴落をすべて通知した。逃したのは、すでに浅い段階を通知済みだった長期下落の深掘り2件（日経平均1965年、米国株1896年）だけ |

過去の比較であり、将来の暴落を同じように捉えられることを保証するものではありません。

日経平均はFREDの `NIKKEI225`（日本経済新聞社の公式終値、1949年〜）を使います。東京の取引日で、東京時間15:45（15:30の取引終了から15分後）を過ぎた日の終値だけを確定値として扱います。FREDはブラウザを名乗る自動取得を止めるため、取得ツール名で接続します。現在値で補う仕組みはなく、FREDに最新日が載るまで待ちます。

S&P500はNasdaqのAPIにないため、Cboe（S&P500オプションの取引所）が公開する1975年以降の日次終値を使います。2026-11-09の確認では、FREDのSP500系列と重なる2,513日のうち2,506日が一致し、残り7日（2018〜2020年）は小さな差でした。

通知条件の正本は `monitors/market-alerts/policy.json`、状態を使った判定の正本は `monitors/market-alerts/alerts.py` です。

- **初回は基準状態を保存するだけです。** 既に到達している段階を、新しく到達した通知として送信しません。
- **同じ下落局面の同じ段階は繰り返し通知しません。** その後さらに深い段階に到達した場合は、新しい段階を通知します。
- **複数の段階を一度に飛び越えた場合は、最も深い段階を1件だけ通知します。** 途中の段階も通知済みとして記録します。
- **通知履歴のリセットには、価格の回復も確認します。** 固定の回復確認価格を保留していない場合、3年高値比が−5%以上になり、かつ前回観測した基準高値に対しても現在の終値が95%以上なら、次の下落局面に備えてリセットします。−5%未満での反発ではリセットしません。
- **古い高値が3年の対象から外れただけでは、リセットしません。** 新しい基準高値では−5%以上でも、前回の基準高値に対して95%未満なら、当日の終値の105%を固定の回復確認価格として保存します。その後、3年高値比が−5%以上、かつ終値がこの価格以上になった時点でリセットします。基準高値がさらに下がっても、この価格は引き下げません。
- **回復確認の保留中に3年高値比が再び−5%未満になったら、固定価格だけを解除します。** 通知済み段階は維持し、次に−5%以上へ戻ったときに回復を改めて判定します。
- **古いデータ、未来の日付、不正なデータでは新しいシグナルを作りません。** そのデータによる通知履歴の更新・再設定もしません。取得時刻と市場データの対象日を分けて検証します。

回復確認の5%は、基準高値の入れ替わりによる誤ったリセットを抑えるための運用ルールです。収益を最大にする数値として検証したものではありません。これらは購入の検討を始めるための通知条件で、最適な購入価格や底値を示す条件ではありません。

## CNN Fear & Greed

Fear / Extreme Fear / Neutral / Greed / Extreme Greed の**カテゴリが変わった場合だけ**、既存の独立通知を継続します。スコアだけの小さな変化では通知しません。

指数の下落通知にも、その時点で利用できるFear & Greedのスコア・カテゴリ・対象時刻を添えます。ただし、Fear & Greedを指数通知の必須条件にはしません。取得が止まっている場合はその旨を表示し、正常な指数通知は続けます。Fear & Greedのカテゴリ変更通知も、指数の閾値到達を条件にしません。

## データ形式と更新

指数のJSONは `schema_version: 2` で、主に次のフィールドを使用します。

| フィールド | 内容 |
|---|---|
| `symbol` | `NDX`・`SPX`・`SOX`・`N225` のいずれか |
| `current_close` / `current_date` | 最新の確定終値と、その取引日 |
| `window_3y_sessions` / `window_3y_start_date` | `756` と、3年の範囲の最初の取引日 |
| `high_3y_close` / `high_3y_date` | 直近3年の最高終値と、その取引日 |
| `drawdown_3y_pct` | 直近3年の最高終値からの下落率（**通知判定**）。判定前に丸めない |
| `ath_close` / `ath_date` / `drawdown_pct` | 全履歴最高終値、その日付、ATH比の下落率。通知本文の参考情報 |
| `window_sessions` / `rolling_high_close` / `rolling_high_date` / `rolling_drawdown_pct` | 直近252取引日の値（v2の判定基準）。古い指示との互換と参考のために残しており、判定には使わない |
| `fetched_at` | 実際に取得・検証した時刻 |
| `current_close_source` | 最新終値の取得元。通常は履歴（`nasdaq-historical` / `cboe-historical`）、履歴の反映前に現在値で補った場合は `nasdaq-quote-info` / `cboe-quote` |
| `supplemented_records` | 現在値APIで補った行数（0または1） |

各指数の通知には、判定に使用した3年高値比と、参考のATH比・過去の暴落の底を区別して表示します。ATH比を3年高値比の代わりに通知判定へ使用しません。

指数ごとの通知状態は `schema_version: 3` / `policy_version: 3` です。`last_high_3y_close` に前回観測の3年高値、`recovery_target_close` に保留中の固定回復確認価格を保存します。通知済み段階と下落局面の識別子も永続保存します。

各指数は独立したworkflowで更新します。取得または検証に失敗した場合は最後の正常JSONを保持し、保存値を読み直しただけで取得時刻を進めません。新しいデータを検証できた場合だけ公開します。

Nasdaqの履歴APIは、取引終了から数時間たっても当日の終値を載せないことがあります（例：2026-11-05の終値は約6時間後でも未反映）。そのため、同じ取得元の現在値（Nasdaqは `/api/quote/<指数>/info`、Cboeは `/quotes/_SPX.json`）も確認し、次の条件をすべて満たすときだけ、その終値を最新の取引日として補います。翌日以降は履歴の値で計算し直します。

- 平日で、ニューヨーク時間16:15を過ぎた確定済みの取引日である
- 市場の状態が取引中（`Open`）ではない。Cboeは最終値の時刻が16:10以降である（2026-11-06の最終値は16:14:59。短縮取引の日は補わず履歴を待つ）
- 履歴APIのどの確定済み行よりも新しい日付である
- 現在値APIの前日終値が、履歴APIの最新終値と一致する（取引日の抜けがない）

市場データが変わらず `fetched_at` だけが進む場合は、1時間に1回だけ公開します（`HEARTBEAT_SECONDS`）。頻繁に起動しても、コミットが増えすぎないようにするためです。

GitHub Actionsの定期実行はベストエフォートであり、設定間隔どおりの実行を保証しません（2026年11月時点では、20分・5分ごとの設定でも実際には4〜8時間に1回でした）。CNN Fear & Greedの独立Watchdogは既存どおり運用します。APIキー・トークンなどの秘密情報はリポジトリへ保存しません。

### PCの常駐アイコン（補助）

所有者のWindows PCで常駐アイコン（`scripts/pc/tray.ps1`）を動かし、15分ごとに `nasdaq-drawdown.yml` / `sp500-drawdown.yml` / `sox-drawdown.yml` / `nikkei-drawdown.yml` / `cnn-fear-greed.yml` を `workflow_dispatch` で起動します。PCにログインしている間だけ動き、既存のGitHub CLI（`gh`）のログインを使うため、新しいトークンは作っていません。PCが止まっている間は、GitHubの定期実行だけに戻ります。

`マーケット監視を起動.vbs` で起動し、`マーケット監視を停止.vbs` かアイコンの右クリック →「終了」で止めます。Windowsログイン時の自動起動は `scripts/pc/install.ps1` で登録します（`-Uninstall` で解除）。

アイコンは藍色の角丸四角に白いろうそく足（株価チャート）で、右上の点の色で状態を表します。丸い緑のアイコン（ちかめし）と見分けられるよう、形と地の色を変えています。

| 右上の点 | 状態 |
| --- | --- |
| 緑 | 正常に監視中（5つのデータとも取得から3時間未満） |
| 青 | 更新処理を起動中・GitHubの更新を待っている・確認中 |
| 黄 | データが3時間以上古い（ChatGPTは判定を保留する）、データを読めない、起動に失敗して再試行待ち |
| 赤 | 起動に3回続けて失敗、`gh` が見つからない |
| 灰 | 一時停止中 |

マウスを重ねると状態を表示します。右クリックで、NASDAQ100・S&P500・SOX・日経平均の3年高値比とFear & Greedの値、前回・次回の起動時刻を確認でき、「今すぐ更新」「一時停止／再開」「GitHubの実行履歴を開く」「終了」を選べます。ダブルクリックでGitHubの実行履歴を開きます。

起動・失敗の記録は `.private/tray.log`、最新の状態は `.private/tray-status.json` に保存します（Git対象外）。表示内容の判定は `scripts/pc/tray-core.ps1` にまとめ、`scripts/pc/test-tray-core.ps1` で検証します。

Windowsは通知領域アイコンの表示設定を「実行ファイル＋番号」で覚えるため、他のPowerShell製アイコン（番号1）と分けて固有の番号 `28013` を使います。`install.ps1` はこの番号の設定だけを「常に表示」にします。設定はWindowsのタスクバーが次に起動したとき（再起動・サインイン後）に反映されます。すぐに表示したい場合は、タスクバーの「^」からアイコンをタスクバーへドラッグしてください。

## ChatGPTのスケジュールタスクへの反映

GitHubのコード・JSONを変更しても、既存ChatGPTタスクに保存された監視指示は自動で置き換わりません。`monitors/market-alerts/task-instructions.md` を使い、既存タスクの監視指示を更新してください。実行頻度と通知先は既存設定を維持します。

ポリシーv3への移行では、v1/v2の状態（252取引日比や全履歴最高値比の段階での通知履歴）を引き継ぎません。基準の高値も段階も違うためです。各指数の最初の正常なv3データで基準状態を作り直し、その時点で到達済みの段階は通知済みとして保存します（通知はしません）。2026-11-06の終値なら、NASDAQ100（−13.56%）とS&P500（−5.65%）は到達済みの段階がなく、SOX（−35.84%）は−30%を通知済みとして保存します。日経平均は新しく追加した指数なので、最初の正常データ（2026-11-09は−18.78%）が基準状態になります。

取得データには252取引日の項目も残しているので、指示を差し替えるまでは旧方式の指示でもデータの検証は通ります。

指示の更新、v3の基準状態の保存、正常なデータの読取確認まで行って初めて、スケジュールタスクへの反映完了です。
